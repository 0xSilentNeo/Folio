### Resume started from the beginning
- **What you saw:** Resume on a title page showed your place ("from 12:53"), but the episode started at 0:00. Tapping the episode did the same.
- **What your 5 Nov log shows:**
  - At 19:07 1.23.0 was installed, and the app's folder moved (…/DFBF5E79…/Documents/Media/ became …/986B236C…/). Every sideloaded update moves it.
  - At 19:09:47 Classroom of the Elite S03E12 was opened from its page with no start position ("opts=[]"), and you closed it at 0:07.
  - At 19:10:25 the same episode from Continue Watching resumed ("start=773"): that card still held the old path.
- **Why:** history kept library files by their full path. The pages found an entry by file name when the path had changed, but the player only looked for the exact path. The same file was also saved as "/private/var/…" and as "/var/…" (both are in that log), with the same result.
- **Now:**
  - History knows a downloaded file by its place inside Media, which an update doesn't change.
  - At launch, the entries saved under older installs' paths move to this one. Two entries for one file become one: the one with a place to resume, else the newer.
  - Progress no longer comes from another file with the same name in a different folder (an open item from the 2 Nov review).
- **Tested in the simulator,** where each install also moves the app's folder:
  - Lab Show E2 saved at 0:25 under an older install's path, Resume on.
  - Before: the page said "Resume from 0:25" and the player was asked for no start position.
  - After: "start=25", including with a few-second false start saved under the new path. The simulator's history went from 46 entries to 13, one per file.
  - Unit tests for the move and the merge.
- **Needs your phone:** Resume and episode taps after installing this build. Once the entries have moved, the log says so: "[history] library files: N entr(ies) moved to this install's folder".
