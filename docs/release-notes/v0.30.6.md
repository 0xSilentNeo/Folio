*Renamed from v1.30.6 on 19 Nov 2026, when the version numbers started again at 0.90.0. The app in this build still calls itself 1.30.6.*

**Test build.** Download `Folio-1.30.6.ipa` below and sideload it. It updates 1.30.5. It's a pre-release until you've checked it on your phone.

This release is the code check you asked for: a review of everything 1.30.4 and 1.30.5 changed, the fixes, then a second review of the fixes and fixes for what that found.

### Playback
- **One recovery per bad stretch of a stream.** When the hardware decoder failed on bad data, Folio rebuilt it 0.3 s later, twice. Each rebuild went back to the keyframe before the damage, still in the buffer, so the new decoder got the same bad data. One bad read cost several freezes and jumps. It's now rebuilt once, 12 seconds past the bad stretch, and a trip to Control Center, a call or PiP during those seconds no longer cancels it.
- **Fewer needless reconnects.** The waits right after a seek, an opening or a return to Folio, while a new connection is still speeding up, no longer count towards reopening a slow stream. Three short hiccups alone don't either: they need 4 seconds of waiting between them. A link that dies just after a seek still reconnects.
- **Fill stays Fill** when the decoder restarts, and Anime4K isn't reloaded for it.
- **Skip lookups:**
  - A file whose own chapters give the skips no longer asks the anime databases (AniList, ids.moe, AniSkip).
  - The same lookup is never asked twice at once.
  - A library file's next episode has its skips looked up ahead, as a stream's does.
  - A reconnect keeps what was skipped and a dismissed Up Next card.
- The Metal renderer sizes its frames from the shaders actually on (a show's own Anime4K mode, Anime4K paused while the phone is hot), not from the saved settings.

### A freeze at first launch
- On a fresh install Folio could freeze at launch. A settings observer made a background thread wait for the main thread, while the main thread waited for that thread. It has been there since 1.28.10; installs that already had library metadata never hit it.

### Search
- **The tabs and pills stay at the top** as you scroll, on a solid band so the list doesn't show through.
- **No jumping while you type.** The last text's results stay, dimmed, until the new ones come.
- **Less IMDb traffic.** The fuller title lists are asked from 3 letters and a short pause, after the suggestions. An empty answer is remembered for 5 minutes, and an unreadable page isn't taken as "no results". Too many requests made IMDb hold title pages and episodes for 30 seconds.
- **No wrong or flashing messages:**
  - The "N results in Library" hint no longer shows while offline.
  - The Library tab no longer spins while IMDb answers.
  - "No titles match" no longer flashes.
  - "N results in Search" shows a count only when it's the whole list.

### Downloads
- **"Simultaneous downloads" holds with no network.** Each file waiting for one used to free its place, so the whole queue started; back on Wi-Fi, 24 files could run at once.
- **Stop and resume:**
  - The pill's play button resumes only what was paused this time, not files paused long ago.
  - iOS's stop button on the Lock Screen and in the Dynamic Island pauses the downloads.
  - Turning on mobile data restarts files waiting for Wi-Fi.
- **Space:**
  - A failed file downloaded again carries on where it stopped, or its partial file is deleted.
  - Partial files left behind by earlier versions are cleaned up at launch.
  - Free space is kept for the files already downloading, and a file that would fit once they're done waits instead of failing.
- An error page from a reused download address goes back through the original link instead of failing the file.

### Home and Continue Watching
- **A downloaded film is one card**, the newer of the stream and the copy, and the server's browser still knows the stream's place.
- **Lighter:**
  - Pull to refresh no longer waits for a full Real-Debrid re-listing.
  - Continue Watching and the search index are no longer rebuilt every minute.
  - Large libraries near the folder limit keep releases already indexed.
- A title's ⋯ menu waits for its IMDb id, and a widget's link to a library card works after a sideloaded update.

### Sync and the kids profile
- **Sign In Again.** When a service needs a new sign-in, Settings has a button for it and what's waiting is kept; Disconnect deletes it.
- **Nothing lost:**
  - A token revoked on the service's site asks for a new sign-in.
  - A sync asked for during another runs after it.
  - Anime plays missing an id while offline wait instead of being skipped.
- **Kids profile:**
  - A Keychain error can't turn the kids profile off.
  - The Airing widgets don't show grown-ups' shows while it's on.
- **Also:**
  - An old update banner gives way to the newest.
  - A preset writes only what it changes.

### Tested
- **Unit tests pass:** 827, about 60 of them new.
- **Simulator UI tests pass:** search, the kids profile, Settings search, Home, episode rows, the Real-Debrid row, launch (also on a freshly erased simulator), and two that open, play and close a file.
- **Not checked on a phone:**
  - streaming from Real-Debrid over 5G;
  - the AirPlay list's animation;
  - downloads when the network goes and comes back;
  - iOS's stop button.

### Known and left
- **Skip pills:** an anime stream's first episode now gets them after the file opens, a few seconds later than in 1.30.5, when the chapters show they're needed. Later episodes are looked up ahead.
- **Downloads:** iOS doesn't say whether its stop button or its own time limit ended the background downloads, so both pause them.
- **Kids profile:** the Airing widgets are empty while it's on.
